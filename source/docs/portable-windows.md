# MarketGO Portable — Windows x64 / Python

공식 Python 임베디드 런타임과 필요한 라이브러리를 함께 넣었습니다.
start.bat가 포함된 runtime/python.exe로 Python 수집·계산 서버를 실행합니다.
Python·Go·Node·PowerShell·DB를 별도로 설치할 필요가 없습니다. 실행 중 pip나 프로그램을 설치하지 않습니다.
이 PC에서 거래소에 직접 연결하며, 인터넷이 필요합니다.

1. 이전 MarketGO 실행 창을 종료합니다. 브라우저만 닫으면 수집 프로그램이 남을 수 있습니다.
2. ZIP 전체를 새 폴더에 압축 해제합니다.
3. MarketGO 폴더의 **start.bat**를 더블클릭합니다.
4. 준비되면 기본 브라우저가 열리고 데이터가 들어옵니다.

실행 창을 유지해야 수집이 계속됩니다. 종료는 실행 창에서 Ctrl+C입니다.
브라우저가 열리지 않으면 http://127.0.0.1:20560/ 를 직접 엽니다.
오류는 화면의 '수집 연결 확인', logs/launcher.log, logs/runtime.log에서 확인합니다.
이미 실행 중이면 실행 창을 또 열지 말고 브라우저만 엽니다.

## 데이터와 보관

- 오늘 코인 보기: 공식 활성 KRW 마켓 목록과 5개 거래소의 최근 24시간 티커, 약 10초 갱신.
- 실시간 보기·점유율: 실제 WebSocket 체결을 수집해 계산하며 화면은 0.5~1초마다 조회합니다.
- 24시간 선택 시 좌측 실시간 표와 우측 구성·그래프는 모두 공식 24시간 티커를 사용합니다.
- 디지털엑스(코빗)·고팍스 포함. 공지 수집과 AI 작업은 없습니다.
- 실시간 체결 이력은 메모리에 있으며 종료하면 사라집니다. 공식 시간봉은 `data/index-hours.sqlite3`에 남습니다.
- 다시 켜면 공식 24시간 티커는 다시 받아오고, 실시간 체결은 실행 시점부터 쌓입니다.
- 실행하면 최근에 끝난 공식 1시간봉을 자동 수집하고, 이후 정시가 지난 2분 뒤 새 시간봉을 수집합니다.
- 오늘의 자료 선택에서 ‘수집한 시간봉’을 고르면 최근 24개의 끝난 시간 구간 중 저장된 금액을 봅니다. 과거 날짜는 저장된 한국 날짜의 시간봉을 읽습니다.
- 시간봉 원화 거래금액은 빗썸·업비트·코인원만 수집합니다. 디지털엑스·고팍스의 미제공 금액은 빈 값입니다. 일부 시간만 저장됐다면 부분 자료로 표시합니다.
- PC가 꺼져 있던 시간이나 실패한 과거 요청을 다시 채우지 않습니다. 24시간 티커를 시간봉으로 저장하거나 합산하지 않습니다.
- 새 ZIP으로 업데이트할 때 프로그램을 완전히 종료하고 기존 `data` 폴더 전체를 새 Windows 폴더에 옮기세요. 이 폴더를 지우면 저장된 인덱스가 사라집니다.
- 최대 최근 24시간, 25만 개 코인·초 집계 단위까지 보관합니다. 초과하면 오래된 구간을 비우고 부분 관측으로 표시합니다.
- 미수신·오래된 금액을 0으로 채우지 않습니다. 연결 중단·종료 동안의 체결을 복구하지 않습니다.

## 구성

- start.bat: 실행기
- app/: Python 수집·계산·HTTP 서버 소스
- data/: 자동 생성되는 로컬 시간봉 기록. Git·배포 ZIP에 포함하지 않습니다.
- runtime/: Python.org의 공식 Windows x64 임베디드 Python
- vendor/: 고정 버전 WebSocket 라이브러리·공개 인증서 묶음과 라이선스
- web/: 화면 파일
- DEPENDENCIES.json: 의존성 버전, 공식 다운로드 URL, SHA256

TLS 인증서 검증은 유지하며 Windows 인증서와 포함된 공개 인증서 묶음을 사용합니다.
Windows x64용입니다. 회사 보안 정책·거래소 차단 등 개별 환경 차이는 오류 로그에서 확인해야 합니다.
Windows와 Mac은 같은 Python 프로그램과 같은 화면 파일을 사용합니다. 플랫폼별로 런타임과 실행기만 다릅니다.

## PC 시각 차이

시작할 때 최소 두 거래소의 검증된 HTTPS 응답 시각이 일치하는지 확인하고,
프로그램의 수집 기준 UTC만 보정합니다. Windows 시스템 시각은 바꾸지 않습니다.
이후에는 단조 증가하는 경과 시간을 사용하므로 실행 도중 PC 시각을 바꿔도 수집 기준이 뛰지 않습니다.
조회일도 서버 기준을 사용합니다. 시각 차이가 크면 화면의 '수집 시각 자동 보정 적용'에서 차이를 확인합니다.

시스템 날짜가 크게 틀려 HTTPS 인증서 검증 자체가 실패하면 Windows의 자동 시각 동기화를
확인한 뒤 다시 실행해야 합니다. 인증서 검증을 끄거나 잘못된 시각의 체결을 무조건 받아들이지는 않습니다.
